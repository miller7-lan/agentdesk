# AgentDesk 群聊界面重新设计

> 2026-11-16。前提：微信端保持一对一（见 [WECHAT_OMC_PLAN.md](WECHAT_OMC_PLAN.md)）；**AgentDesk 端以群聊形式呈现**：你、组长和各个 agent 都是同一个群里的成员。
> 现有界面：左侧会话列表 / 中间单 agent 对话 / 右侧 Diff·终端·文件面板 / 底部状态栏（`src/index.html`）。

## 1. 核心概念

| 概念 | 含义 | 来自哪里 |
|---|---|---|
| **项目** | 一个代码仓库或一类工作。**按项目建群** | 本地创建；微信对话对应一个固定的「云任务」项目 |
| **群聊** | 项目内的多成员对话，组长参与 | 每个项目一个主群 |
| **单聊** | 你和某一个 agent 的一对一对话，组长不参与 | 从成员列表直接发起；现有的单 Codex 会话就是一种单聊 |
| **成员** | 你、组长、各执行 agent、本机、系统 | 群配置 |
| **消息** | 成员的发言：派活、回复、提问、结论 | task-runner 的账本 + Codex app-server 事件 |
| **任务** | 一次派活及其执行过程（容器、状态、日志、产物） | task-runner 的 SQLite（与微信 `/ls` 同一来源） |

### 1.1 默认成员

| 头像 | 名称 | 身份 | 说明 |
|---|---|---|---|
| 你 | 你 | 人 | 可以从桌面或微信发言；微信来的消息带「📱 微信」标记 |
| 组 | 组长 | Claude Code + OMC | 默认接收你的消息，负责拆任务、派活和验收 |
| cx | Codex | 执行者 | 实现、跑测试；也包括 AgentDesk 现有的 Codex 桌面会话 |
| cc | Claude | 审查者 | 只读审查 |
| ag | Antigravity | 顾问 | 长文档阅读、第二意见 |
| gk | Grok | 顾问 | 实时信息、第二意见 |
| 本 | 本机 | Windows 本机能力 | 桌面和文件工具；每次调用都要你在 AgentDesk 里审批 |
| · | 系统 | 事件 | 掉登录、额度用尽、超时、成员状态变化 |

成员**同时用颜色和文字缩写区分**（不能只靠颜色），每个成员的颜色在深色和浅色两套主题里都要定义。

### 1.2 微信与群的关系

- 微信一对一对话 ↔ AgentDesk 里固定的「云任务」群。你从手机发的消息、组长回复你的消息，在群里都能看到；群里其它 agent 之间的交流**不推送到微信**，只推送最终结论和需要你处理的事项。
- 在桌面端建的其它群（例如「agentdesk 开发」）不和微信相连；如果需要，可以在群设置里打开「完成时通知微信」。

### 2.1 左栏：项目 → 群聊 / 单聊（替代会话列表）

```
▾ ◇ agentdesk            ●2
    # 群聊（组长 cx cc ag）  3
    @ Codex                    ← 单聊
    @ Grok                     ← 单聊
▸ ☁ 云任务  📱            ●1
▸ ◇ 周报整理
  [+ 新建项目]
```

- 项目是第一层，展开后是该项目的**主群聊**和若干**单聊**；项目行汇总未读数和进行中任务数。
- 项目行显示：图标（☁ 云任务 / ◇ 普通项目）、项目名、📱（连着微信）、**进行中任务数徽标**。
- 排序：有待审批的置顶 → 有进行中任务的 → 按最近消息时间。待审批用警告色圆点，最显眼。
- 新建单聊：在群聊右侧「成员」页点某个成员的「私聊」，或在左栏项目下点「+」。

### 2.2 中间：群聊时间线

**消息类型**（这是重新设计的核心）：

| 类型 | 外观 | 说明 |
|---|---|---|
| 人的消息 | 右对齐或带「你」头像；来自微信的带 📱 | 现有的用户气泡 |
| agent 发言 | 左侧头像 + 名称 + 模型小字；正文用 Markdown 渲染 | 只放**结论和对人说的话** |
| **派活卡片** | 组长发出，标明「→ @执行者」；卡片内显示状态、耗时、内存；**状态原地更新**，不重复刷新消息 | 一个任务一张卡片，点击后在右侧「任务」页打开详情 |
| 过程折叠行 | 「▸ 运行了 4 个命令 · 改了 2 个文件」，默认折叠，展开后是现在的工具调用列表 | 复用现有的工具调用渲染（`live.js` 的 item → kind/icon 映射） |
| **审批卡片** | 警告色边框，写明**哪个成员**请求、在**哪台机器**上做什么；按钮：批准 / 本群内一直允许 / 拒绝 | 复用现有审批逻辑；新增「请求者」和「目标机器（VPS / 本机 / 容器）」 |
| 引用回复 | 审查者回复时引用执行者的结果，显示一条细线连接两条消息 | 让交叉审查一眼可见 |
| 提问卡片 | agent 需要你回答（`waiting_input`），带输入框，可以直接回复 | 对应 OMC 的 ask-user-question |
| 系统事件 | 居中灰色细行 | 掉登录、额度用尽、换执行者、超时、成员加入 |

**防止刷屏**（4 个 agent 同时干活时最重要）：
- 主时间线**只显示发言级的消息**：派活、结论、提问、审批、系统事件。命令输出、日志、思考过程一律折叠，或者放到右侧任务详情里。
- 同一个任务的连续进度合并进**同一张派活卡片**，不新增消息。
- 顶部筛选栏：全部 / 只看 @我 / 只看某个成员 / 只看待处理。

### 2.3 输入区

- 群聊中「发给：组长 ▾」：默认发给组长，也可以切换成直接发给某个成员（相当于 `@cx`）或全员。
- **直接 @ 执行者时绕过组长**，不抄送，组长不会因此被唤醒。但这些任务仍然会进入项目的任务列表，写权限锁仍由 task-runner 统一控制（同一项目同一时刻只有一个成员能写），所以不会和组长派出的任务同时改同一份代码。
- 单聊中没有「发给」选择，消息只发给对方；单聊里产生的任务同样记入项目任务列表。
- 输入 `@` 弹出成员列表，**每个成员带当前状态**（▶️ 忙 / ✅ 空闲 / 🪫 额度用尽 / 🔑 需登录），不可用的成员置灰并说明原因。
- 输入 `/` 弹出命令：`/duo`、`/team`、`/stop #17`、`/ls`，以及现有的 `/compact`、`/model`、`/review`。
- 权限模式从「每条消息选一次」改为**群级设置**（放在群设置里），输入区只显示当前模式的小标签，避免每次都要选。
- 附件、模型、推理强度选择保留；当消息发给组长时隐藏模型选择（由组长按角色分配）。

### 2.4 右侧面板

在现有的 Diff / 终端 / 文件之前，新增两个页签：

- **成员**：每个成员一行，显示状态、当前任务号、耗时、容器内存、登录和额度状态；点击某个成员即可在时间线中筛选他的消息。底部是资源区：VPS 内存、swap、容器占用（x/2）。
- **任务**：本群的任务列表（与微信 `/ls` 同源），选中后显示详情：状态时间线（queued → running → …）、实时日志（`logs -f`）、产物、停止和重跑按钮。
- 现有的 **Diff** 页签按任务筛选，显示「#17 改了哪些文件」；**终端**页显示所选任务的容器日志。

### 2.5 状态栏

保留连接、桌面控制、主题等现有项，新增：`容器 1/2`、`内存 2.9G`，以及四个 CLI 的状态小标（✅ / 🔑 / 🪫）。点击任意一个小标，跳到右侧「成员」页。

## 3. 状态与颜色规范

统一的状态集合，与 task-runner 和微信端一致：

| 状态 | 图标 | 颜色变量 |
|---|---|---|
| 排队 / 待命 | ⏳ | `--muted` |
| 运行中 | ▶️ | `--accent` |
| 等待你回答 / 等待审批 | ❓ / ⚠ | `--warn` |
| 成功 | ✅ | `--ok` |
| 失败 / 超时 | ❌ / ⌛ | `--danger` |
| 已取消 | ⏹ | `--faint` |
| 需重新登录 | 🔑 | `--warn` |
| 额度用尽 | 🪫 | `--warn` |

成员颜色：在 `styles.css` 的两套主题里各新增 `--m-lead`、`--m-cx`、`--m-cc`、`--m-ag`、`--m-gk`、`--m-local` 六个变量，与状态颜色区分开（状态用实心圆点，成员用头像底色），两套主题都要检查对比度。

## 4. 数据模型（渲染层）

```js
Project { id, name, kind: 'cloud' | 'local', wechat: boolean, policy, pinned }
Conversation { id, projectId, type: 'group' | 'direct', members: MemberId[], unread }   // direct 时 members = ['you', 某成员]
Member  { id: 'you'|'lead'|'cx'|'cc'|'ag'|'gk'|'local'|'system', name, short, color, backend, status, quota, auth }
Message { id, conversationId, from: MemberId, to: MemberId[], kind: 'text'|'dispatch'|'steps'|'approval'|'question'|'event',
          replyTo?, taskId?, via?: 'wechat'|'desktop', body, ts }
Task    { id, projectId, conversationId, assignee, status, steps[], container, startedAt, endedAt, memPeak, artifacts[] }
```

数据来源：
- **云端成员**（组长、cx/cc/ag/gk 容器任务）：task-runner 的 status API（经 SSH 本地端口转发），使用 SSE 或长轮询推送增量。
- **AgentDesk 现有的 Codex 会话**：作为成员 cx 的一个「桌面实例」，仍然走现有的 app-server 事件；现有的 `item/*` 事件转成 `steps` 消息。
- **本机**：本机工具调用以 `approval` 加 `steps` 消息的形式出现，审批逻辑不变（ROADMAP 的权限矩阵是前置条件）。

## 5. 对现有代码的影响

| 现有 | 改为 |
|---|---|
| 侧栏「会话」列表（`#sessionList`） | 项目 → 群聊 / 单聊 两级列表 |
| 中间多标签页（`#tabs`） | 去掉，用左栏切换；保留 Ctrl+Tab 快速切换最近的群聊 / 单聊 |
| 现有的单 Codex 会话 | 迁移为对应项目下的「@ Codex」单聊，历史 thread 保留 |
| `live.js` 中的单会话 item 渲染 | 拆为 `views/timeline.js`（消息类型渲染）+ `views/dispatch-card.js` + `views/approval-card.js`；工具调用的渲染逻辑原样复用到折叠行里 |
| `modeSelect` 每条消息选一次 | 群级设置 |
| 右侧面板 Diff / 终端 / 文件 | 新增「成员」「任务」页签，Diff 和终端按任务筛选 |
| `data.js` 的 mock 数据 | 改为群聊 mock，仅用于离线模式和截图测试 |
| 状态栏 | 新增容器、内存、CLI 状态 |

建议先完成 ROADMAP M2 中的「拆分 `live.js`，状态集中管理」，再做这次界面改版，否则会在 988 行的文件里继续堆逻辑。

## 6. 实施步骤

1. **原型（2 天）**：先做一个可点击的静态原型（离线 mock 数据，沿用现有配色变量和深浅主题），确认布局、消息类型和防刷屏策略，再进入正式开发。
2. **渲染层重构（3-4 天）**：拆分 `live.js`，引入 Project / Conversation / Member / Message / Task 的状态仓库；现有的单 Codex 会话先作为「@ Codex 单聊」跑通，保证功能不退化。
3. **群聊视图（4-5 天）**：时间线的各种消息类型、派活卡片原地更新、筛选、@ 成员和 / 命令、群级权限设置。
4. **右侧面板与状态栏（2-3 天）**：成员页、任务页、资源与 CLI 状态。
5. **接入 task-runner（2-3 天）**：status API 的推送接入、微信消息标记、「云任务」群与微信对话的对应。
6. **验收**：深浅两套主题截图（沿用 `AGENTDESK_SHOT` 机制）、长时间 4 个 agent 并发的刷屏测试、审批卡片只能在本机操作的验证。

## 7. 已确定

1. **按项目建群**：每个项目一个主群聊。
2. **直接 @ 执行者不抄送组长**；写权限冲突由 task-runner 的项目级写锁兜底。
3. **群聊和单聊都支持**：单聊是项目下你和某一个 agent 的一对一对话，现有的单 Codex 会话迁移为单聊。
