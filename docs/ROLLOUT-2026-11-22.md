# 本次上线（2026-11-22）：最新功能，以及 VPS2、本机各要做什么

以 main 上最新提交为准（含 `f6d3e96` 权限统一）。顺序：**先 VPS2，再 Mac，最后 Windows**。新客户端连旧主控时，新功能会报「不支持的操作」。每一端动手前先看 [DEPLOY.md](DEPLOY.md)。

## 一、最新功能（这次上线的重点）

### 1. 四家权限统一放到最大

Claude、Codex、Grok、Antigravity 拿同一套工具、同一段权限说明（`orchestrator/permission-prompt.js`），问它们「你有哪些权限」应该回答一致。

| | Claude | Codex | Grok | Antigravity |
|---|---|---|---|---|
| 自己的 shell（VPS2 沙盒，可联网） | 开 | 开，改写轮次联网 | 开 | 开（`command(*)`） |
| 子代理 | 开（Task、Agent） | 自带 | 开（spawn_subagent、workflow） | **待改，见第五节** |
| 联网搜索、读网页 | 开 | 开 | 开 | 开；`execute_url` 仍关，**待改** |
| 本机命令 `local_shell` | 用户本人权限 | 同左 | 同左 | 同左 |
| 唯一挡住的 | AgentDesk 自己的密钥目录（`~/.agentdesk`、应用数据目录） | 同左 | 同左 | 同左 |

- **原生单聊**：Claude、Grok、Antigravity 的系统提示和 Codex 的 `developerInstructions` 是同一段中文，按电脑是 Mac 还是 Windows 写 zsh/bash 或 PowerShell/CMD；只读规划轮次用只读版本。
- **群聊**：每一步末尾加同一段英文权限说明（组长规划那一步除外，它的提示以 JSON 结尾）。Claude 只读步骤也能用 shell（目录只读挂载，改不了）；Codex 改写步骤联网。
- **Mac 群聊本机命令**：和单聊一样只挡 AgentDesk 密钥目录，SSH 密钥、钥匙串不再挡，`git push` 能用。
- **仍然关着的**：要人在键盘前的工具（提问、计划模式切换）、Grok 的定时任务和监视器、Grok 的图片和视频生成。只读挂载和 `windows_*` 文件工具照旧过滤凭据目录（它们会把文件内容送到 VPS2）。

### 2. Mac 原生单聊

Codex、Claude、Grok、Antigravity 在「完全访问」下直接读写 Mac 项目，用 `local_shell` 在 Mac 上跑任意命令。详见 [MAC-NATIVE-CHAT.md](MAC-NATIVE-CHAT.md)。

### 3. 之前已合并、这次一起上线的

群聊一组一个工作台、改方向保留做了一半的工作、失败自动换模型和选模型弹窗、节点换模型、组长临时申请权限（每次你批准、只在该群聊有效）、只读挂载、按额度分流、实时额度（含 Claude）、模型列表自动更新。清单见 [UPDATE-DIRECTION.md](UPDATE-DIRECTION.md) 第二、三节。

## 二、VPS2 要做什么

1. **拉代码并安装**（按 DEPLOY.md §1「更新代码」，先排空）：
   ```sh
   cd <VPS2 上的仓库目录> && git pull --ff-only
   $ADMIN maintenance on "deploy f6d3e96"; $ADMIN maintenance     # 等 ready=true
   sudo bash orchestrator/install-ubuntu.sh                       # 新文件 permission-prompt.js 会一并复制
   sudo systemctl restart agentdesk-orchestrator
   $ADMIN maintenance off
   ```
2. **原生单聊服务端**：`native-project-session-host.js` 和 `chat-server.js` 由同一个安装脚本复制，不用单独操作。原生单聊里的 CLI 进程在新开的单聊才用新权限；已经打开的单聊关掉重开一次。
3. **配置检查**（`/etc/agentdesk-orchestrator/config.json`，改前先备份）：
   - `adapters.*.sandbox` 要配好：Claude、Grok、Antigravity 的 shell 和子代理只在沙盒里开，没配沙盒就没有。
   - `groupFeatures.anyLead` 设为 `true`：组长可以是任意组员（已定方向）。
   - 群聊本机能力要开对应开关：`groupFeatures` 里的 `localStages`、`localCopy`、`credentialSandbox`（Mac 上只挡 AgentDesk 目录）、`envFix`。
   - 其余配置照 [UPDATE-DIRECTION.md](UPDATE-DIRECTION.md) 第三节（`routing.implement` Codex 排第一、`homeMounts`、`discoverModels` 等）。
4. **确认生效**：`systemctl is-active agentdesk-orchestrator`、`journalctl -u agentdesk-orchestrator -n 50` 无报错、`ad doctor` 各 CLI 正常。
5. **回滚**：`git checkout 998092c`（权限统一之前），再跑安装脚本并重启。

## 三、Mac 要做什么

1. **更新应用**：Actions 产物 `agentdesk-mac`，或 `npm ci && npm run dist:mac -- --arm64`。原生单聊、Codex 的权限说明（`developerInstructions`）都在应用里，必须更新应用。
2. **更新后台 Bridge**：群聊本机命令只挡 AgentDesk 目录这一改动在 Bridge 里（`windows.js`、`group-local.js`、`platform-mac.js`）。按 DEPLOY.md §3「更新后台 Bridge」拉代码或复制 `orchestrator/*.js`，然后 `launchctl kickstart -k gui/$(id -u)/<标签>`。
3. **配置**：Bridge 配置保留 `"mountHome": true`；原生单聊的项目要选「本机项目」并选好目录，同名工作区 `write: true`。
4. **验收**：见第六节。

## 四、Windows 要做什么

1. **更新应用**：Actions 产物 `agentdesk-windows` 的安装包覆盖安装（Windows 的 Bridge 在应用进程里，更新应用就够了）。
2. **配置**：Bridge 配置 `"mountHome": true`。Windows 上群聊本机命令本来就不强制挡凭据目录，这次无变化。
3. **验收**：见第六节，`local_shell` 用 PowerShell。

## 五、Antigravity 也要一样（在 VPS2 上改代码）

Antigravity 现在已经拿到同一段权限说明（它和 Claude、Grok 共用 `chat-server.js` 的 `instructions()`），shell、读写文件、联网搜索也开着。和另外三家还差两处，改法如下：

1. **`orchestrator/chat-server.js` 的 `permissions`**（`providerArgs` 末尾，`deny: ['execute_url(*)', ...]` 那段）：
   - 把 `'execute_url(*)'` 从 `deny` 移到 `allow`，和其他三家「联网读网页」一致。
   - 如果 agy 有子代理或浏览器子代理工具，把它的权限名加进 `allow`。名字以 `agy --help` 或它的设置文档为准，不要猜；不确定就先跳过这一条。
2. **`orchestrator/adapters.js` 群聊的 Antigravity 权限**（`if (name === 'antigravity' && provider.template)` 那段）：同样把 `'execute_url(*)'` 从 `deny` 移到 `allow`；子代理同上。
3. **权限说明里的名字**：`orchestrator/permission-prompt.js` 里两处「Claude、Codex、Grok」改成「Claude、Codex、Grok、Antigravity」，群聊那段英文 `the same for Claude, Codex and Grok` 改成 `the same for Claude, Codex, Grok and Antigravity`；`test/unified-permissions.test.js` 对应的两条断言一起改。
4. **测试**：`npm test`，要求结果是 `# fail 0`（不是只看有没有 `# fail`）。再按第二节安装、重启。
5. **提交**：提交到 main 前先 `git pull --ff-only`；真实 IP、令牌不进仓库。

## 六、上线后验收（每台电脑）

1. 四家各开一个「完全访问」单聊，问「你有哪些权限」：回答应该一致，都提到 `local_shell`、子代理、联网，只挡 AgentDesk 密钥目录。
2. 各跑一次 `git status` 和项目测试；各推送一个测试分支（`git push`），应能成功。
3. 让它跑 `ls ~/.agentdesk`：应该被拒绝（Mac 上是 Operation not permitted）。
4. 让 Claude 和 Grok 各开一个子代理查点资料，确认能用。
5. Mac 上发一个群聊任务，让某一步在本机跑 `git push` 测试分支，应能成功。

把每一项结果（通过，或失败加报错原文）记下来。
