# CLI 接入现状评估（2026-11-17，基于 `main` `0c8305d`）

> 范围：VPS2 主控 `orchestrator/` 对各家 CLI 的接入：`adapters.js`、`scheduler.js`、`quotas.js`、`mcp.js`、`admin.js`、`vps2.example.json`。
> 结论：**「规划 → 分步执行 → 补丁审核 → 写回本机」的主流程已经能跑通，但离全面还有明显差距**：缺 Antigravity，规划不是 Claude，只有 Codex 有实时额度，不记录 token 用量，agent 在执行中碰不到本机的命令和桌面。

## 2. 已经做得好的

- 每个步骤独立的 worktree、进程组、会话和日志；取消时整组进程结束；单次调用 15 分钟超时、4 MB 输出上限；日志里的密钥自动打码。
- 只读步骤如果改了文件会被拒绝；补丁先留在 VPS2，审核后才写回本机，写回前核对 Git 基线。
- 规划时会把各模型的擅长方向和价格交给规划者，要求「用最便宜但能胜任的模型」，并提示订阅也算额度。
- 规划结果先给你在群聊里确认，再执行。
- 管理命令覆盖了提交、状态、取消、应用补丁、核对、切换线路、上传下载和查看额度。

## 3. 差距（按对你的影响排序）

### 3.1 和已定分工直接冲突

1. **没有 Antigravity 适配器**：你订阅了 Antigravity，并且定位是「侦察和主力」，目前完全没法用。
2. **规划由 Codex 执行**（`scheduler.js` 的 `planner` 和 `group-planner`）：已定的是 Claude 当组长，并且没有「Claude 看摘要验收」这一步。
3. **配置样例全是 API Key 计费**（`vps2.example.json`）：你的四个 CLI 都是订阅登录。代码支持使用已登录的 CLI 目录，但没有登录流程、登录检查，也没有掉登录识别。

### 3.2 影响「省 Claude / Codex 额度」

4. **只有 Codex 有实时额度**；Claude 要另外配置钩子才有，Grok 和 Gemini 没有任何额度来源。按额度调度时对它们是「盲」的。
5. **不记录 token 用量**：Codex 的 `--json` 和 Claude 的 `stream-json` 输出里本来就有用量，现在只取了最终回复文字。没有用量就无法验证「到底省没省」。
6. **额度用尽时不会换人**：失败只会用同一个 CLI 重试一次（并且只在进程异常退出时），不会改派给其他 CLI，也没有升级到 Claude 的规则。

### 3.3 影响 agent 能做的事

7. **执行中碰不到本机的命令和桌面**：给 agent 的本机工具只有 4 个只读操作（列目录、文件信息、**按文件名**搜索、分块读取）。没有按内容搜索、不能跑命令、不能用桌面工具。Windows 上的测试只能在任务最后由主控统一跑一次。
8. **测试只能是一条固定命令**：在提交任务时指定；agent 改完后不能自己在本机跑测试再修。
9. **Codex 沙盒默认不联网**：worktree 里需要装依赖的测试可能跑不起来。
10. **只能输入文字**：任务提示最长 12000 字，不能附带截图或文件。

### 3.4 运维和可见性

11. **只保留每步最后一条回复**（前 12000 字），没有过程中的流式进度；群聊里只能看到步骤结束后的摘要。
12. **管理命令缺**：列出所有任务、查看某一步的实时日志、CLI 登录 / 健康检查（doctor）、清理。
13. **没有 Docker 隔离**：CLI 直接以服务账户运行。

## 4. 建议的补齐顺序

| 顺序 | 内容 | 解决 | 估计 |
|---|---|---|---|
| 1 | Antigravity 适配器（先在 VPS2 上确认无交互参数、输出格式、会话恢复） | 3.1-1 | 1 天 |
| 2 | 规划和验收改由 Claude；加「侦察 → 规划 → 简报 → 改代码 → 测试 → 审查 → 验收」流程 | 3.1-2 | 2 天 |
| 3 | 订阅登录：`login` / `doctor` 命令、掉登录和额度用尽识别、配置样例改为订阅 | 3.1-3、3.4-12 | 1 天 |
| 4 | 从各 CLI 输出里记录 token 用量；Grok / Gemini / Antigravity 尽量找到额度来源，找不到就靠「额度用尽」报错识别 | 3.2-4、5 | 1 天 |
| 5 | 失败和额度用尽时改派或升级到 Claude | 3.2-6 | 1 天 |
| 6 | 给 agent 加本机工具：按内容搜索、在授权项目里跑白名单命令（需审批）；Codex 测试步骤允许访问软件包源 | 3.3-7、8、9 | 2 天 |
| 7 | 步骤流式进度推到群聊；`ls` 和 `logs -f` 管理命令 | 3.4-11、12 | 1 天 |
| 8 | Docker 隔离（见 [TASKS.md](TASKS.md) 第 2 节） | 3.4-13 | 3～4 天 |

第 1～3 项和你的分工设计直接相关，建议先做。
