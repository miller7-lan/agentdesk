# 安全审查与防封（2026-11）

范围：桌面端（Electron）、VPS2 编排器与登记服务、VPS1 Relay、各 AI CLI 的账号使用方式。
结论：整体设计偏保守，没有发现能直接拿到 VPS 或本机控制权的漏洞。主要风险集中在两处：一是**公网入口的滥用和被识别**，二是**AI 账号的风控**。本次已直接修掉能在代码里修的部分，其余需要在 VPS 上操作的列在“需要你做的”。

## 1. 暴露面一览

| 入口 | 位置 | 对外 | 认证 | 现状 |
|---|---|---|---|---|
| SSH 22 | VPS2 | 是 | ed25519 证书（8 小时）+ forced-command，`agentdesk` 用户禁 TTY、禁转发 | 好；全局 sshd 设置不由仓库管理（见 3.1） |
| 登记服务 HTTPS 443 | VPS2 | 是 | 密码（scrypt N=32768）→ 签发证书和 Relay 令牌 | 有限速：每 IP 5 分钟 6 次、全局 48 次、同时校验 ≤2 |

## 2. 本次已修复

### 2.1 Relay：单个地址可以占满全部连接槽
- 问题：Relay 全局只有 16 个连接槽，且不分来源。一个扫描器只要建 16 个 TLS 连接、什么都不发，就能让真正的客户端连不上（每个空连接最多占 5 秒，可以无限重复）。错误令牌也可以无限次尝试（令牌 256 位，猜中不可能，但会消耗资源、刷日志）。
- 修复（`relay/server.py` `AddressGuard`）：
  - 每个地址最多同时持有 4 个**未认证**连接（`--pending-per-address` 可调）。已认证的连接不计入。
  - 10 分钟内令牌错误 8 次的地址，拒绝连接 15 分钟。
  - 每分钟清理过期记录。测试：`relay/tests/test_relay.py` `AddressGuardTest`。
- 配套（`orchestrator/transport.js`）：客户端收到 `unauthorized` 后改为约 10 分钟才重试。令牌被拒不会自己恢复，原来每几秒重试一次，既是无效流量，也会让同一出口 IP（比如同一办公室的 2–3 人）被上面的规则一起拦下。

### 2.2 重连加随机抖动，尾部更长
- `remote.js`（桌面端 SSH）：重连间隔 1/3/5/10/20/30 秒后增加 60 秒一档，每次随机提前 0–20%。
- `orchestrator/service.js`（Bridge SSH）：同样加抖动，上限从 30 秒放到 60 秒。
- 目的：网络被干扰时，多台客户端不会在同一时刻整齐重拨。固定节奏的重复失败连接本身就是一种可识别的流量特征。

### 2.3 Electron 权限默认全给
- Electron 默认批准网页发起的摄像头、麦克风、定位等权限请求。界面有 CSP 且不加载远程内容，风险不高，但没有理由留着。
- 修复（`main.js`）：除剪贴板写入（“复制”按钮要用）外一律拒绝。

### 2.4 登记密码长度
- 登记端口对公网开放，密码是扫描器和 SSH 证书之间唯一的东西。限速只能拖慢猜测，真正让猜测无望的是长度。
- 修复（`write-password-verifier.js`）：少于 16 个字符拒绝生成校验文件。已部署的校验文件不受影响；如果现在的密码短于 16 位，建议换掉。

## 3. 需要你在 VPS 上做的（按优先级）

### 3.1 全局 SSH 加固（VPS1、VPS2 都做）
仓库只管理 `Match User agentdesk` 这一段，全局设置不在仓库里。建议 `/etc/ssh/sshd_config.d/10-hardening.conf`：

```
PermitRootLogin prohibit-password
PasswordAuthentication no
KbdInteractiveAuthentication no
MaxAuthTries 3
LoginGraceTime 20
MaxStartups 10:30:60
```

用 `sshd -t` 检查后再 `systemctl reload ssh`；**先确认你自己的密钥能登录再断开当前会话**。OpenSSH 9.8 及以上自带 `PerSourcePenalties`（默认开启），可替代 fail2ban；版本较旧时装 fail2ban（只开 sshd jail）。

### 3.2 防火墙只开用到的端口
目前安装脚本不配置防火墙。建议：

```
# VPS2
ufw default deny incoming && ufw allow 22/tcp && ufw allow 443/tcp && ufw enable
# VPS1
ufw default deny incoming && ufw allow 22/tcp && ufw allow 22022/tcp && ufw enable
```

Docker 发布的端口会绕过 ufw。步骤隔离容器只需要出站，**不要用 `-p` 发布任何端口**。

### 3.3 登记服务不必常开
证书 8 小时过期，所以登记服务确实要能随时访问。如果团队成员的出口 IP 固定，可以在 443 上只放行这些 IP（`ufw allow from <IP> to any port 443`），扫描器就完全看不到它。

### 3.4 自动更新
`updates.js` 只接受 HTTPS feed，默认关闭，这是对的。没有 Windows 代码签名和 macOS 公证之前**不要打开**：未签名时，feed 或下载被替换就等于在每台电脑上执行任意程序。

## 4. 防封：IP 和端口

### 4.1 为什么会被封、会被封什么
- **端口被干扰**：从国内连海外 VPS，SSH 是最容易被识别的协议之一（握手特征明显，与端口号无关）。常见现象是长时间大流量 SSH 后连接被重置、变慢，或者该端口被临时阻断，同一 IP 的其他端口通常正常。
- **IP 被封**：一般是同一 IP 上出现了明显的代理特征流量，或者 IP 段整体被封。AgentDesk 本身没有代理流量，风险主要来自同机还跑了别的东西。
- **自签证书 + 非标准端口**：Relay 用 22022 端口和自签 CA，主动探测时会显得不像普通网站，但它只回应合法握手，探测得到的信息很少。

### 4.2 现有设计已经在帮你
- **双路由**：SSH（VPS2:22）是主线，Relay（VPS1:22022，TLS）是备线，走不同的 IP 和协议。一条被干扰时，另一条还能用。这是目前最有效的防封手段，**保持两条都配置好**。
- **流量很小**：传的是 JSON 指令、补丁和日志，不是持续大流量，被流量规则盯上的概率远低于代理。
- **SSH 心跳**：`ServerAliveInterval=20`，空闲连接不会被中间设备悄悄断掉后长时间无响应。

### 4.3 建议（从易到难）
1. **Relay 对外改用 443 端口**：TLS 跑在 443 上最不显眼。服务单元清空了全部 capability（`CapabilityBoundingSet=`），不能直接绑定 443。最省事的做法是在 VPS1 上把 443 转发到 22022，服务本身不动：`iptables -t nat -A PREROUTING -p tcp --dport 443 -j REDIRECT --to-ports 22022`（用 `netfilter-persistent` 保存）。然后把客户端的 `relayPort` 改成 443，防火墙放行 443。VPS1 的 443 已被别的服务占用时不适用。
2. **Relay 用域名和正规证书**：给 VPS1 配一个域名和 Let's Encrypt 证书，TLS 握手里的 SNI 和证书链就和普通网站一样。需要客户端改为信任系统 CA，或同时信任两套。这是后续开发项，见 TASKS.md。
3. **SSH 换非 22 端口**：能减少扫描噪音，但对识别 SSH 没有帮助。可做可不做。
4. **出问题时先切线路，不要反复重连**：客户端已经有退避和抖动，不要手动连续狂点“重连”。
5. **备一个 IP**：VPS 被整体封时，换 IP 后只需更新客户端配置里的 host 和 known_hosts，证书和令牌不受影响。
6. **同一台 VPS 上不要跑代理**：这是 IP 被封最常见的原因，AgentDesk 的 IP 会被连带。

> 未采用：WebSocket + CDN 中转。它能隐藏源站 IP，但会让 CDN 看到所有流量（Relay 本来就不是端到端加密，见 `relay/PROTOCOL.md`），对这个规模也过重。如果以后真的出现整段 IP 不可达，再考虑。

## 5. 防封：AI 账号风控

这一块的风险比 IP 被封大，而且代码修不了，只能靠使用习惯。

| 风险 | 原因 | 建议 |
|---|---|---|
| 地区不支持 | Claude、OpenAI 都按 IP 所在地区限制服务 | VPS 机房选在服务支持的地区；不要让 CLI 经过出口会变化的代理 |
| 数据中心 IP | 部分服务对机房 IP 更敏感，可能更多地要求验证 | 只在 VPS2 这一个固定 IP 上登录；登录一次后长期使用，不要频繁登出登入 |
| 同一账号多地同时使用 | 同一订阅在“国内家里 IP”和“海外 VPS IP”同时活跃，是典型的共享或盗号信号 | 每个订阅只在一个地方使用。CLI 只在 VPS2 上登录；本机桌面版尽量不要同时登录同一账号 |
| 多人共用一个订阅 | Claude Pro/Max、ChatGPT Plus/Pro 等个人订阅条款通常不允许多人共用 | 2–3 人同时开发时，最稳妥的是每人自己的订阅，或使用团队版（Team / Business）。共用个人订阅属于条款风险，系统可以运行，但封号风险由账号承担 |
| 自动化高频调用 | 短时间大量请求会触发限流 | 已有：`maxConcurrentTasks` 默认 2、每个 CLI 一个进程锁、额度到软上限就让出。不要为了提速调高这些值 |

## 6. 其他观察（不急）
- **Windows 上 0600 权限无效**：令牌和证书文件在 Windows 上靠用户目录的 ACL 保护。电脑只有你一个账号时问题不大。
- **Relay 不是端到端加密**：TLS 在 VPS1 终止，VPS1 能看到明文（`relay/PROTOCOL.md` 已说明）。VPS1 要和 VPS2 同等对待，不要给别人登录。
- **全局登记限速可被用来拖延登记**：扫描器打满全局 48 次后，正常用户在当前 5 分钟内也登记不了。代价是最多等 5 分钟，换来的是对猜密码的硬上限；3.3 的 IP 白名单可以同时解决。
- **agent 本机命令**：只有 `agentCommands` 里列出的命令能被 agent 触发，默认只有 `git-status` 等只读命令。加新命令前想一下：它会不会改文件、联网或读取机密。
