# AgentDesk 更新方向（2026-11-20）

目标：群聊像一个自己会干活的小团队。组长（Claude）摸清你的电脑和项目、做规划，把活派给合适的成员，失败了自己补救，只在真正需要你拍板的地方打扰你。

本文记录已经定下的方向、这一轮合并了什么、部署要做什么、哪些还没在真机上验证，以及接下来的顺序。具体操作步骤见 [UPGRADE-2026-11.md](UPGRADE-2026-11.md) 和 [UPGRADE-PROMPTS.md](UPGRADE-PROMPTS.md)。

## 一、已经定下的原则

### 1. 组长

- 组长始终是 Claude，只做规划、诊断、验收，这一条由代码强制。
- 组长用哪个 Claude 模型由你在群聊里选，默认是最新的 Opus。组长的每一步都会明确把模型传给 CLI，不会落到账号默认的模型上。
- 组长读你电脑的权限最高：能只读你的整个用户目录，凭据目录除外。

### 2. 权限按职责，不按模型

哪个成员、哪个模型接了这一步，都按这一步的职责拿同一套权限。

| 职责 | 读项目 | 读项目以外的本机文件 | 改动 |
|---|---|---|---|
| 规划、诊断、验收（组长） | 快照 | 只读挂载，加项目以外的只读工具 | 不改 |
| 侦察、查资料、审查 | 快照 | 只读挂载；挂载断开时才用工具 | 不改 |
| 改代码 | 快照 | 只读挂载 | 在 VPS2 副本里改，以补丁形式交给你审核；项目以外的文件只在组长标记了这一步时才能写 |

- **快照**：任务开始时从你电脑上取一份项目快照，包括未提交的改动和新文件（`.gitignore` 排除的除外）。`.env`、密钥这类敏感文件会跳过，并在群里提示。快照不动你的暂存区。
- **只读挂载**：你电脑上的 Bridge 只读地提供用户目录，VPS2 用 `sshfs` 挂载。CLI 用自己原生的读文件、搜索直接读，不用一个个调工具。凭据目录在你电脑上就过滤掉了。读的时候项目目录会被藏起来，避免和快照混用两个版本。

### 2b. Claude、Codex、Grok 权限统一放到最大（2026-11-22）

三家用同一套工具、同一段权限说明（`orchestrator/permission-prompt.js`），所以它们自己描述的权限也一致：

| | Claude | Codex | Grok |
|---|---|---|---|
| 自己的 shell（VPS2 沙盒，可联网） | 开（原生单聊以前关着） | 开，改写轮次联网（以前不联网） | 开 |
| 子代理 | 开（以前关） | 自带 | 开（以前 `--no-subagents`） |
| 联网搜索、读网页 | 开 | 开 | 开 |
| 本机命令 `local_shell` | 用户本人权限，只挡 AgentDesk 密钥目录 | 同左 | 同左 |

- **原生单聊**：Claude、Grok（以及共用同一服务的 Antigravity）的系统提示和 Codex 的 `developerInstructions` 是同一段文字，按电脑是 Mac 还是 Windows 写 zsh/bash 或 PowerShell/CMD。只读规划轮次用只读版本。
- **群聊**：每一步（规划那一步除外，它的提示以 JSON 结尾）末尾加同一段英文权限说明；Claude 在只读步骤也能用 shell（目录是只读挂载，改不了），Codex 改写步骤联网。Mac 上群聊本机命令和单聊一样只挡 `~/.agentdesk` 和 AgentDesk 应用数据目录，凭据目录（SSH 密钥、钥匙串）不再挡，`git push` 能用。
- **仍然关着的**：需要人在键盘前的工具（提问、计划模式切换）、Grok 的定时任务和监视器（会活过这一轮）、Grok 的图片和视频生成（花钱）。只读挂载和 `windows_*` 文件工具照旧过滤凭据目录：这两样会把文件内容送上 VPS2，和在你电脑上跑命令不是一回事。

### 3. 谁来干活

- **改代码**默认只给 Codex，同一项任务用同一个 Codex 模型。Codex 接不了，或者你点名别人时才换。
- **侦察、查资料、审查**按额度均衡：额度用得明显少的成员先接。
- **模型**优先用各成员最新一代的模型。Antigravity 的常规步骤用默认的 flash 档。
- **额度页「分工与降级顺序」**：
  - 每种活都可以补充成员和具体模型，你排的顺序优先；
  - 列出的成员都接不了时，其他能做这种活的成员自动补上。
- **模型列表**每 6 小时自动跟各家官网同步一次。Claude 的列表来自 Anthropic 的模型列表接口。

### 4. 出了问题怎么办

- **CLI 中途断了**：先用同一个模型、同一个会话接着做一次。
- **一步失败**：输入框旁的「自动接手」开着时，直接换下一个模型，接着上一个模型已做的改动继续。同一步最多换 3 次；还不行交给组长；组长也解决不了，再弹窗让你选成员、模型和思考程度。「自动接手」关着时，一失败就弹窗。
- **权限不够**：一步因为权限被拒而没做完时，不再换模型（权限按职责给，换了模型也一样），而是由组长判断这一步到底需要什么权限，再弹窗问你。申请可以**超出这台电脑配置允许的范围**（避免莫名其妙的限制），但每次都要你批准，而且要写清楚具体是什么：
  - 读某一个文件夹（写出路径）；
  - 改某一个文件夹里的文件（项目以外）；
  - 运行某一条命令（写出程序和参数，在项目文件夹里运行，不经过 shell）；
  - 操作桌面。

  你可以选「允许这一步」「这项任务都允许」或「拒绝」：
  - 你点「允许」时，批准记录写在**你自己电脑的 Bridge 上**，VPS2 自己创建不了这种授权，只能在任务结束时把它收回。
  - 授权只对这一个群聊里的这一项任务有效，不会影响其他群聊、其他任务或单聊，任务结束或 6 小时后收回。
  - 允许后，这一步回到原来的会话接着做；拒绝时，它不用这个权限把能做的做完，并说明还缺什么。
  - 凭据目录、`.git`、绕过补丁直接改项目、让 Claude 做成员的活，无论怎样都不会开。
  - 组长认为不需要更多权限时，会给出另一个做法，让这一步接着做。
- 按阶段预先授权（`fix/group-stage-permissions`）：
  - 你的请求和某一步都点名了某个盘或桌面时，这一步自动带上对应的文件工具；
  - 要交付的文件必须有写入回执才算完成；
  - 方案要求在本机检查时，审查、诊断、验收可以运行配置好的命令。
- - **还没开始的步骤**：泳道卡片和分工进度里有「换模型」。正在运行的和已经完成的步骤不能换。

### 5. 少打扰你

- **方案确认**有三档：
  - 「小方案自动」（默认）：不改文件、或 3 步以内的方案直接开始；
  - 「每次确认」：每个方案都等你确认；
  - 「全部自动」：所有方案都直接执行，用到你电脑的也不问。
- 唯一一定要你审核的，是把补丁应用到你电脑上的项目。
- **同一个群聊就是一个工作台**：
  - 任务还在进行时，直接在群里说话，就是让组长修改当前任务。组长判断每一步是继续、补一句指导接着做、停下，还是新增步骤，做了一半的内容不丢。
  - 只有当前任务结束后，新消息才开始新任务。
  - 要指定成员，就在消息开头写 `@成员`，只对这一条消息生效。
- 「自动接手」和单聊里的「完全访问」等选择会被记住，重启后不变。

### 6. 看得见进度

- **派遣单聊**按「成员 + 具体模型」分开，排版和普通单聊一样：
  - 你可以在里面指导成员，做完后结果自动回到群聊；
  - 同一个成员、同一个模型的后续派活复用原来的单聊，同时在跑才另开一个；
  - 每个群聊最多保留 10 个。
- **泳道**：每条泳道有竖线和节点圆点，交接线按步骤之间的依赖画，并行的步骤从共同的前置步骤分叉。
- **额度**：额度页打开时每 10 秒刷新一次。Codex、Grok、Antigravity、Claude 都尽量读真实用量，读不到才按调用次数估算，卡片上会注明「估算」。

## 三、部署顺序与要改的配置

顺序：**先 VPS2，再 Mac，最后 Windows**。新客户端连旧主控时，新功能会报「不支持的操作」。

VPS2：

- 拉取最新代码，运行 `sudo bash orchestrator/install-ubuntu.sh`，然后重启主控服务。
- `routing.implement` 改成 Codex 排第一，或者整项删掉用默认值。
- `adapters.claude.models` 列出 Claude 的各个模型。可选 `adapters.claude.leadModel`。保留 `"discoverModels": true`。
- 只读挂载：
  1. 安装 `sshfs`；
  2. 配置加 `"homeMounts": true`；
  3. 启用 `agentdesk-home-mount.service`；
  4. 每把 Bridge 公钥的强制命令后面加上对应的挂载 socket。
  
  详见 [orchestrator/OPERATIONS.md](../orchestrator/OPERATIONS.md)「只读挂载本机用户目录」。

Mac：

- 更新应用和后台 Bridge。
- Bridge 配置加 `"mountHome": true`。

Windows：

- 更新应用，Bridge 配置加 `"mountHome": true`。
- Windows 原生单聊按 [WINDOWS-NATIVE-CHAT-DEPLOY.md](WINDOWS-NATIVE-CHAT-DEPLOY.md) 先验收再启用。

## 四、还没在真机上验证的

这些都有自动测试，但没在真实的 VPS2 和你的电脑上完整跑过。部署后优先检查：

1. **只读挂载**：
   - 挂载由单独的 `agentdesk-home-mount.service` 完成，主控服务能不能看到这个挂载还没在真机确认。看不到时会自动退回 MCP 读取，不影响使用，但就没有直接读的好处。
   - 走 VPS1 跳板时的挂载也没测过。
2. **Claude 的两个接口没有公开文档**：用登录令牌读实时额度（`/api/oauth/usage`）和读模型列表（`/v1/models`）都是参考开源项目写的。读不到时会退回旧做法（每轮记录的用量、配置里的模型）。
3. **Codex 不在沙盒里**：Codex 不在 bwrap 沙盒里运行，挂载里的项目目录对它来说只靠提示词约束；其他 CLI 是真的被藏起来了。凭据目录对所有 CLI 都是在你电脑上就过滤掉的。
4. **快照校验变严了**：快照包含新文件之后，做完快照如果你又在项目里新建了文件，应用补丁时会提示版本已变化。
5. **整条流程**：改方向时组长逐步判断、失败自动接手到弹窗、节点换模型，这些都只在模拟数据下验证过。
6. **Windows 原生单聊**：根据它的文档，Grok 和 Codex 因为订阅额度不足，真实模型这一轮还没验收完。
7. **权限统一**：Codex app-server 的 `developerInstructions`、Grok 开子代理、Claude 原生单聊开 Bash，都只在模拟 CLI 下测过。验收：三家各开一个完全访问单聊，问「你有哪些权限」，回答应该一致；再各跑一次 `git push` 测试分支。

## 五、外部审查提出的三个问题（2026-11-20 检查结果）

1. **本机命令只能跑预先配置的命令**：
   - 单聊：已经解决。Windows 原生单聊有 `local_shell`，能跑任意 PowerShell 或 CMD 命令，绑定当前项目，可以停止，断线后还能找回结果。
   - 群聊：仍然只能跑配置在 `agentCommands` 里的命令。群聊的改动还在 VPS2 副本里，没回到你电脑上，直接在真实项目里跑临时命令，测的不是这次的改动。所以方向是：群聊里的临时命令在下面第 3 点的隔离目录里跑（目录里是「你的项目 + 这次的补丁」），而不是直接放开在真实项目里跑。
2. **群聊要求 VPS2 已经有本机的提交**：**已经修复**。VPS2 的仓库缺你当前的提交时，主控让 Bridge 把缺的提交打成 Git bundle 自动同步过去，只传 VPS2 没有的部分，不用手动推送。单次上限 20 MiB；第一次同步整个历史超过上限时，手动推送一次即可。
3. **Windows 测试在补丁写回真实项目之后才跑**：配置了隔离测试的项目已经解决。在 VPS2 工作区配置 `isolatedTests` 和 `defaultIsolatedTest`，在 Windows Bridge 配置 `isolatedCommands` 后，补丁会先在 Windows 的临时目录里编译和测试，通过后才让你应用（见 [GROUP-WINDOWS-TESTS.md](GROUP-WINDOWS-TESTS.md)）。没配置的项目仍按旧流程：应用补丁后再在本机测试。建议所有需要 Windows 构建的项目都配置上。

## 六、接下来的方向

**P0：先把真机跑通**

- 按 [UPGRADE-PROMPTS.md](UPGRADE-PROMPTS.md) 让 Mac 和 Windows 上的 agent 逐项验收，重点是上面第四部分。
- 发现的问题先修，再做新功能。

**P1：让「直接读」的收益看得见，堵上剩下的口子**

- 群聊里的临时本机命令（动态 PowerShell 或 CMD）放到隔离测试目录里跑，复用单聊的 `local_shell`，可以停止，结果可以找回。

- 统计每项任务的 MCP 调用次数、重复读文件次数、CLI 调用次数和用时，对比直读挂载前后的差别。
- 让 Codex 也看不到挂载里的项目目录：给 Codex 也套一层隔离，或者在挂载这一层就按任务过滤。
- 快照版本校验只看补丁改到的文件，避免无关的新文件挡住应用补丁。
- 在 VPS1 跳板上验证挂载和原生单聊的线路切换。
- Windows 原生单聊验收完成后正式启用；Mac 也按同一套协议做原生单聊。

**P2：构建和失败处理更省心**

- Windows 和 macOS 的构建、测试交给固定的 Runner，结果和快照编号绑定，失败只重跑受影响的部分。
- 自动接手按失败原因选择策略：
  - 卡住或超时：接着做；
  - 报错退出或审查不通过：从头重做；
  - 同一个错误出现多次：不再反复叫醒组长。
- 每个群聊的派遣单聊多了以后，侧边栏折叠显示。

## 七、不变的规则

- 真实 IP、私钥、令牌、密码只放在各端的配置或 GitHub secret 里，仓库只放 `*.example.json`。
- 在 VPS 上动手之前先告诉你；部署或修改 VPS2、Windows、Mac 之前，先读 [DEPLOY.md](DEPLOY.md)。
- 界面文字和文档用中文。
