# 群聊 v7 在 Windows 上（Q6：按平台分开的文档）

代码：`orchestrator/platform-win.js`（平台部分）、`orchestrator/group-local.js`（Bridge 端操作）。开关见 [GROUP-V2.md](GROUP-V2.md)。

**Windows 上没有选定任何操作系统强制机制。** M1 没有选择 (i)–(iv) 中的任何一项；M2 的原文是“Windows取决于M1”；O3 的原文是“Windows 不变”。因此：

## 本机命令（`localStages`）

- 读取、审查、诊断、验收步骤用 `local_shell_run` 在**原项目**里运行任意命令，默认 PowerShell，也可以选 cmd。
- 命令以本人的权限运行，**凭据目录不受保护**。工具结果和群聊里都会注明“Windows 未强制保护凭据目录（仅 AgentDesk 工具和挂载会拒绝）”。
- AgentDesk 自己的文件工具、挂载和补丁，对凭据目录、`.git` 内部、AgentDesk 目录仍然一律拒绝（N2）。

## 写代码步骤的本机副本（`localCopy`；M3 为推荐做法）

- 普通拷贝：用 `fs.cp` 递归复制，不用硬链接；链接按原样复制，不跟随。
- 副本同样有 2 GB 上限，并要求剩余空间至少是副本的 2 倍。
- **副本没有强制隔离**：命令可以用绝对路径写原项目，界面会标注“副本未强制隔离（Windows）”。
- 检测方式：每条副本命令运行前后各取一次原项目的快照版本，如果不一致，群聊会显示“副本里的命令运行期间原项目有改动”，并写入审计。这只是检测，不是阻止，也不是持续监听。

## 环境修复（`envFix`）

与 Mac 相同：
- 以补丁写入原项目；
- 写入前保存原内容，可以撤销；
- N2 三类路径拒绝；
- 同步回云端。

## 未在真机验证

以上行为只在 Linux 上做了测试。Windows 上需要真机验收的项目：

- 拷贝副本；
- PowerShell 和 cmd 下的命令；
- 检测提示；
- 补丁应用。

单聊终端打包检查在 Windows 上仍未通过（Ctrl+C 后 shell 没有响应），群聊交互终端也没有做。客户端（含新版 Bridge）还没有在用户的 Windows 上安装或替换。
