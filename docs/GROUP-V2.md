# 群聊 v7：已实现部分、开关与未完成项

依据《群聊重构方案规范 v7》（主人已审阅；计划文件 v1–v7 留档在任务目录）。原则：以稳定性优先，每项能力都有独立开关，可单独关闭、可回滚、兼容旧功能。

## 开关（`/etc/agentdesk-orchestrator/config.json` 顶层 `groupFeatures`）

| 开关 | 能力 | 决定 |
|---|---|---|
| `timeline` | 群聊消息按时间排序：分工进度随变化移到最新位置，本机测试和验收总结按实际时间放置 | 要求 6、Q5 |
| `snapshotNotice` | 项目快照上传云端并校验通过后，群聊显示“项目已上传云端”（含改动文件数、跳过的敏感文件数、sha256） | 要求 7 |
| `planFailureAdvice` | 规划失败时群聊给出原因，以及 2–3 个可直接打开的单聊（成员、模型、权限档、预填首句） | 要求 4 |
| `anyLead` | 规划、诊断、验收可以由任意成员担任（各自的“成员@模型”链）；Claude 也可以接成员的活 | Q1 |
| `leadChainQuota` | 当前组长链里的成员超过软线后只做组长的活；不在组长链里的成员只看硬线 | N3 |
| `patchDownload` | “下载补丁”按钮：把 VPS2 上待应用的补丁下载到本机 `~/.agentdesk/patches/<任务>.patch`，sha256 校验通过后才显示“补丁已下载” | Q4、要求 7 |
| `applyPause` | 应用补丁期间，该工作区新的本机命令先等待（最多 60 秒）；已在运行的命令和交互终端不受影响 | O2 |

- **缺省值**：没写的开关一律视为关闭，旧配置的行为不变。
- **关闭某一项**：把它设为 `false`，然后重启 `agentdesk-orchestrator`。
- **写错时**：键名或取值写错，服务会拒绝启动，并报 `invalid_group_features:<名称>`。
- **桌面端**：通过 `route_status` 的 `groupFeatures` 读取这些开关，界面跟着开或关。
- N4（验收允许同一成员）不需要开关：现有代码本来就不禁止同一成员验收。
