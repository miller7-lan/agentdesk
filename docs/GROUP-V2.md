# 群聊 v7：已实现部分、开关与未完成项

| `leadAdvice` | 规划失败时，由组长链中下一位可用成员（跳过刚失败的那位）总结单聊建议；得不到可用回复时保留规则建议 | 要求 4 | 否 |

- **缺省值**：没写的开关一律视为关闭，旧配置的行为不变。
- **关闭某一项**：把它设为 `false`，然后重启 `agentdesk-orchestrator`。
- **写错时**：键名或取值写错，服务会拒绝启动，并报 `invalid_group_features:<名称>`。
- **桌面端**：通过 `route_status` 的 `groupFeatures` 读取这些开关，界面跟着开或关。
- **旧版 Bridge**：遇到需要新版 Bridge 的操作，工具会返回 `bridge_update_required`，群聊照旧继续，不会走到别的路径上。
- **N4**（验收允许同一成员）不需要开关：现有代码本来就不禁止。
- **M3 只是推荐**：本机副本的做法（Mac 用 APFS 写时复制，Windows 普通拷贝；上限 2 GB，剩余空间要有副本的 2 倍；包含 `.git`、`.env` 和被忽略的依赖目录；项目根目录必须是 Git 仓库根）是 Claude 的推荐，不是主人逐项决定的。超出上限或条件不满足时不建副本，改代码只在云端进行，群聊会说明原因。

## 旧版 Bridge 和故障时的安全降级（2026-11-22 审计后）

- **能力探测**：VPS2 用 `group_capabilities` 询问这台电脑的 Bridge 能做什么。结果按工作区缓存 5 分钟；离线时不缓存，下次再问。旧版 Bridge 不认识这个操作，就按旧版处理。
- **写项目以外的位置**：Q2 和 R1 扩大了“谁可以写”，前提是写前备份。Bridge 不能备份时：
  - 步骤在 v7 之前本来就能写的照旧可写；
  - 新扩大的那部分（没有规划标记的写代码步骤、审查、诊断、验收、env-check）返回 `bridge_update_required`，不会在没有备份的情况下放行；
  - Q2 免确认也只在已知 Bridge 能备份时生效，否则规划照旧要确认。
- **M2 在旧版 Bridge 上**：已有的白名单命令照旧能运行（兼容旧功能），但结果里写明 `credentialSandbox: not_applied_old_bridge`，不冒充已经受保护。
- **O2**：命令等过补丁应用的，结果里写明“补丁应用中，命令已等待”，或者“补丁应用超时，命令已开始”（60 秒后放行）。
- **服务重启**：重启时正在写入的环境修复记为“结果未知”，连接恢复后核对。即使 `envFix` 已经关闭，也会核对和补传云端。
- **关闭开关后**：已有的环境修复记录和项目外文件的备份仍然显示，仍然可以撤销或还原。
- **本机副本**：副本改动传回云端前，先在临时索引里试应用，失败就不碰写代码步骤的工作树；万一应用中途失败，原样恢复写代码步骤自己的改动。
- **云端冲突**：环境修复同步到云端时发生冲突，交给诊断（组长）处理（E9）。
- **Mac 副本位置**：放在 `~/Library/Caches/AgentDesk/group-copies`。放在 Bridge 状态目录下会被 sandbox 关掉，副本里的命令就没法运行。
- **组长链写建议**（`leadAdvice`）：
  - 每个规划失败只试一次，每个任务最多两次；
  - 维护模式和服务停止时不运行；
  - 只读，最长 4 分钟；
  - 不会因为任务被反复保存而重复调用 CLI。

## E1–E12 的落实

| # | 落实情况 |
|---|---|
| E1 验证、E7 补丁应用后 | 本机测试失败后，先插入一个 env-check 步骤（每个失败结果一次，每个任务最多两次）。它判断是不是环境问题，是就打环境修复补丁，然后重新测试；是代码问题就照旧退回写代码的步骤。补丁应用后的测试失败会进入诊断，诊断同样可以修 |
| E2 诊断、E4 审查、E5 验收 | 这些步骤都有 `local_env_fix` |
| E3 规划、E6 总结 | 不能修（规划在方案确认之前；总结不做核验） |
| E8 回传云端 | 修复同时写进云端快照（形成新的基线），并应用到每个云端工作树；写代码的步骤的补丁按新基线重新生成，不会带上这次修复 |
| E9 | 本任务有写步骤在运行时，修复会先等它结束（如果它正在等本步骤占用的 CLI，就直接拒绝，避免死锁）；不同任务之间用写令牌互斥。同步到云端时发生冲突，会记为“冲突，交给诊断” |
| E10 | 本机回复丢失时，记为“结果未知”，连接恢复后在 tick 时核对；本机已经写入但没传到云端的，自动再传 |
| E11 | 打修复的步骤可以写项目以外的位置（R1），写前备份，可还原（`outside_restore`） |
| E12 | 工具说明里写明：凡是为了让项目在本机运行而做的改动（包括平台相关源码）都算环境问题（R3），并可标记 `platformSource` |
